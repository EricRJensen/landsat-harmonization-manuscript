# Landsat sensor harmonization

Source code for *Cross-Sensor Differences in Landsat Collection 2 Vegetation
Indices Alter Environmental Inference* (manuscript dated September 4, 2026).

The repository contains the scripts used to generate the paired Landsat sample,
fit the harmonization relationships, produce the manuscript figures and tables,
and run the Landsat Harmonization Explorer. Large analysis inputs and generated
figures are not stored in Git.

## Analysis scripts

Run scripts from the repository root. File paths that a user may need to change
are defined near the top of each R script. The Earth Engine JavaScript files are
intended to be copied into the [Earth Engine Code Editor](https://code.earthengine.google.com/)
and run there.

| `figure_01_extract_grsa_timeseries.js` | Export the GRSA annual Landsat series |

| `tables_s03_s04_view_geometry.py` | Tables S3-S4 |

and validation are in `analysis/common/manuscript_methods.R`.

## Paired Landsat sample

The analysis-ready paired-sample file is not stored in this repository. It will
be published as `SR_Landsatsamples_Covariates.parquet` in the following Zenodo
record, which is still a draft:

https://zenodo.org/records/22033662

Place the downloaded file at:

```text
data/external/SR_Landsatsamples_Covariates.parquet
```

The file used for the manuscript contains 4,820,405 rows and has SHA-256:

```text
a2ef688d76bebc9f3be71b6dcb7e675380192c6df063141e44c9bfbdbe1b6e95
```

The `leohs_*` scripts document how paired samples and covariates were produced.
They do not provide a bit-for-bit reconstruction of the archived parquet because
the random seeds and exact merge command for the two original LEOHS runs were
not retained. See `REPRODUCIBILITY_NOTES.md` for additional details.

## Other analysis inputs

The remaining inputs are generated by the corresponding extraction scripts and
should be placed under `data/external/` using the filenames defined near the top
of the analysis scripts. They are not distributed with this repository.

- Figure 1 uses the GRSA Landsat CSV exported by
  `figure_01_extract_grsa_timeseries.js`.
- Figures 3 and S4 use the park trend GeoTIFFs exported by
  `figure_03_s04_extract_park_trends.py` and an NPS boundary file.
- Figures 4, S5, and S6 use the Landsat and gridMET-DROUGHT exports produced by
  the three Figure 4 Earth Engine scripts.
- Figure 5 uses the annual field CSV produced by
  `figure_05_extract_sims_fields.py`. Its harmonized SIMS collection is
  restricted and is not constructed in this repository.

## Figures S7 and S8: observation sampling sensitivity

`analysis/figure_s07_s08_observation_sampling.py` produces the GRSA supplemental
figures using plotnine and Arial. Figure S7 combines full-record observation
counts, annual April-September means at the same 5,493 locations in every year
of 2000-2022, and mean point-specific Theil-Sen trends with 95% spatial-block
bootstrap intervals. Figure S8 shows the separate 1984-2025 time series, where
the complete-month subset can change each year. A complete month has at least
one valid observation; neither comparison standardizes timing within months.
The fixed sample excludes elevations at or above 3,000 m.

Place these **precomputed summary inputs** in `data/external/grsa_sampling/`:

| File | Contents / use |
|---|---|
| `observation_count_distribution.csv` | Mean valid counts by year and sensor across all 10,000 locations, including zeros (S7A) |
| `valid_acquisition_dates_by_year_sensor.csv` | Valid counts by sensor, year, month, and day; used to verify the observation-count totals |
| `fixed_panel_annual_means.csv` | Annual raw/harmonized, original/equal-month means; `All points` rows select the fixed 5,493-location sample (S7B-C) |
| `fixed_panel_summary.json` | Fixed-sample composition and mean point-specific trends with precomputed 4 km spatial-block bootstrap intervals (S7D) |
| `annual_aprsep_means.csv` | Full-record means over all available points and the annually varying complete-month subset (S8) |

These files were generated by the GRSA observation-sampling analysis in the
companion `landsat_sensor_harmonization` workspace (`src/extract_grsa_ndvi/`),
where they reside in `output/grsa_sampling/`. Inputs are not tracked in this
repository and must be supplied separately. The plotting script does **not**
rerun Earth Engine extraction, harmonization, sample selection, slope estimation,
or bootstrapping; it reproduces the figures from those summary results. It
checks the expected years and sample counts and reconciles acquisition totals
with the count summaries before plotting. Harmonization was applied upstream,
before aggregation; trend estimates are means of point-specific slopes, not
slopes fitted to the plotted spatial means.

Use a separate Python 3.10 environment because these figures require a newer
pandas than the repository-wide analysis requirements:

```bash
python3.10 -m venv .venv-s07-s08
.venv-s07-s08/bin/python -m pip install -r analysis/requirements-s07-s08.txt
.venv-s07-s08/bin/python analysis/figure_s07_s08_observation_sampling.py
```

Arial must be installed; the script fails explicitly rather than substituting
another font. No Earth Engine credentials are needed to render these figures.
Use `--input-dir PATH` and `--output-dir PATH` to override the default locations.
For example, with the companion repository alongside this one:

```bash
.venv-s07-s08/bin/python analysis/figure_s07_s08_observation_sampling.py \
  --input-dir ../landsat_sensor_harmonization/output/grsa_sampling
```

Outputs go to `output/figures/` (ignored by Git):

- `figure_s07_observation_availability_sensitivity.{pdf,svg,png}`
- `figure_s08_complete_record_monthly_sensitivity.{pdf,svg,png}`
- Matching `_caption.txt` files and an S7 `_provenance.json` covering both figures,
  including input/script SHA-256 hashes, font, and plotnine version.

PDF and SVG preserve vector graphics; PNG output is 400 dpi. Missing
complete-month years (1984 and 1990) remain gaps in Figure S8.

## Software

Python dependencies for the analysis scripts are listed in `requirements.txt`.
LEOHS must be installed separately to regenerate paired samples. The archived
run logs identify LEOHS 1.1.2, while the manuscript currently states 1.2.0.

The R scripts use `arrow`, `dplyr`, `ggdist`, `ggplot2`, `ggrepel`, `hexbin`,
`patchwork`, `purrr`, `readr`, `scales`, `sf`, `terra`, `tidyr`, and
`tidyterra`.

The explorer app has separate setup and deployment instructions in `app/README.md`.
Its regional coefficient collection was built for a broader set of use cases
than the manuscript-specific analysis.
